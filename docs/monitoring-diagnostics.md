# 监控与诊断

MoiCalendar 的运行诊断是可选的本地功能。当前版本没有接入远程遥测供应商，也不会向 Azure Static Web Apps、Supabase 或其他服务上传诊断记录。诊断存储失败不会阻止本地日历、备份或云同步。

## 配置

浏览器配置位于 `MoiCalendar:Diagnostics`：

```json
{
  "Enabled": true,
  "RetentionLimit": 200
}
```

- `Enabled` 控制是否记录运行事件。设为 `false` 后不再写入或读取事件，但仍可生成一次性的健康状态报告。
- `RetentionLimit` 控制 IndexedDB 中最多保留的近期事件数，可配置为 1–1000。

诊断抽象由 `IOperationalDiagnosticsSink` 提供。同步、认证和 Realtime 代码只依赖该抽象；将来如需增加远程遥测，供应商实现必须留在基础设施层，并继续执行同样的字段白名单和脱敏规则。

## 收集的运行事件字段

每条事件只包含以下白名单字段：

- 随机事件 ID、UTC 记录时间。
- 应用版本。
- 宽泛的客户端平台分类：Windows、Android、iPadOS、iOS、macOS、Linux 或 Browser。完整 User-Agent 不会保存。
- 事件类型和结果状态。
- 安全的失败类别和短错误码。
- 同步耗时、上传数量、接收数量、冲突数量和重试次数（仅在相关时出现）。

事件类型覆盖同步开始/完成、Push/Pull 失败、Realtime 连接失败、认证刷新失败和云端点可用性失败。原始异常消息不会进入事件。

## 健康状态字段

诊断页面可即时检查：

- 应用版本和宽泛客户端平台。
- 本地 IndexedDB 是否可访问。
- 云后端是否已配置。
- 认证状态（未配置、已退出、已登录或不可用），不包含账号 ID、邮箱或令牌。
- 最近一次成功同步时间、待上传变更数和当前同步状态。
- Realtime 连接状态及功能是否可用。Realtime 状态只表示通知通道，不代表数据已经一致；增量 Push/Pull 仍是唯一权威同步路径。

## 永不收集的字段

标准诊断不会收集：

- 日历名称、日程标题、描述、地点或备注。
- 用户 ID、邮箱、显示名称或设备名称。
- 密码、访问令牌、刷新令牌、Microsoft 令牌。
- WebDAV 密码或其他提供商凭据。
- Authorization 标头、Cookie、请求正文或服务角色密钥。
- 完整 URL、查询字符串、完整浏览器 User-Agent 或原始异常堆栈。

## 为支持人员导出

打开“设置 → 同步状态”，在“运行诊断”区域点击“刷新诊断”可查看当前健康状态和近期运行事件；点击“导出诊断”会下载版本化的 `moicalendar-diagnostics-日期时间.json` 文件。用户可先在页面中检查内容，再自行决定是否发送给支持人员。点击“清除本地诊断”可移除已保存的运行事件，不会删除日历数据或同步状态。

诊断导出与日历备份是两个独立格式。诊断导出不能用于恢复日历，也不会包含备份内容或认证会话。
