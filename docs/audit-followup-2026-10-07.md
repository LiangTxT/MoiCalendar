# 复验清单处理记录（2026-10-07）

基线：`feature/calendar-ux-v2`，`2a9f6df`（v4.2），动手前工作区干净。审计文本只提供读码结论，以下按实际代码与回归测试判断，不执行其中提到的 ACL 修复。

## 已修正

- 云端“保留本地”：C# 与 IndexedDB 均合并同锚点系列的排除记录，并保存到本地与替代发件箱负载。
- 自导出/导入：识别本机合成 UID，更新原 ID；原记录为墓碑时仍跳过，不复活。
- 导入明确 EXDATE：先重映射本地排除记录，再与文件并集；缺失字段仍继承提醒等原始信息。
- 同 UID 多条本地记录：C# 与 JS 按精确更新时间降序、ID 字符串升序选择。
- UTC UNTIL：仅锚点、时区、事件类型未变时保留原精确截止瞬间；开始时间改变时保持截止日。调用者必须明确传递全天类型和时区。
- 草稿全天切换：记住定时起点和时长；已保存全天事件转定时默认 09:00–10:00。
- 整系列更新：检查打开编辑器时的版本，并通过带版本前置条件的原子写入路径提交。
- 坏规则恢复：设置页提供检查列表、原因及二次确认删除；显示路径的失效记录计数可以清理；编辑异常友好处理。
- 坏重复规则不再阻断整份 ICS 导出：保留原规则并显示警告，不偷偷改成受支持规则。非法时区仍需 JSON 备份修复，不假装可正确导出。
- ICS 全天时区、锚点、排除项与颜色往返；日期采用公历不受当前文化影响；支持 Tzfile 前缀，EXDATE 列表去空格。
- 单次排除、导入、恢复、冲突合并加入 100000 条上限，避免生成服务器不能接收的新记录；不截断旧数据。
- Escape 由弹层独占，取消范围选择不会再次关闭恢复出来的编辑器；网格 Space 不额外滚动页面。
- 连续换月清理旧事件焦点；拖动后的背景点击和下一次指针按下清理点击抑制；移除重复 pointer 绑定。
- 快速新建更新草稿不再自关；出现引用直接进入弹层状态，删除静默无效 setter 与裸 ID 死入口。
- 排除次数文案不再把独立编辑算成单纯删除；无变化操作提供轻量反馈；工具栏移除破坏 live region 的 key。
- 日程流刷新以一次区间读取替代逐月读取；多个排除记录重映射只展开规则一次。
- 帮助页显示含 beta 后缀的真实版本，备份与运行诊断保持同一版本；WebDAV 文档明确尚未开放。
- Service Worker 注册有能力检测与失败捕获，失败不阻断在线运行。

## 不照搬的建议

- 用户确认：删除日期以事件自身时区为准。因此“使用显示时区重映射”不是本项目所需行为，保持现状并补充可见说明。
- 冲突解决后不能直接跳到冲突修订号、清除所有延迟项：替代变更未确认前仍须保护本地数据；确认后拉取重放会清理延迟项。新增测试覆盖真正冲突解决、上传确认和另一条未解决变更，证明不会永久钉住或越过其他变更。
- 七位小数秒在 V8 可解析，并不产生 NaN。但原比较精度只有毫秒，已改为保留 .NET tick 精度，测试包含等价时区偏移和 1 tick 冲突。
- 错误提示 CSS、SQL 包装器分发、墓碑初始默认值、CI Node 测试缺失等，审计文本已自行撤回，未做无依据改动。
- `Synchronization.Provider` 原文档已明确“未启用”，不是实际配置入口；补充说明，不删除现有兼容配置契约。

## 保留的边界

- 不通过过期或删除失败发件箱来“优化”延迟游标。要彻底消除冲突期间重复下载，需要可靠持久化延迟远端记录，再独立推进读取游标；不是清字典即可安全完成的修改。
- 不为追求窄 CSP 猜测允许域名：当前 Microsoft、云后端及可选外部提供者的连接策略需按实际部署环境确定，本次未改变。
- 草稿的排除清理数量仍由服务回写，入口先归零避免失败重试残留；未为此改变整个应用服务返回类型。
- Inspector 保持既有固定侧栏布局，不启用尚未接入的锚点浮层视觉。
- 没有新增 beforeinstallprompt 安装引导（属于新功能），也没有改变未完成的后台推送部署。
- 桌面浏览器和 390px 模拟移动视口完成设置入口/布局检查；真实 iPad、Android 手势、系统推送、实际 Supabase 数据库执行未验证。
